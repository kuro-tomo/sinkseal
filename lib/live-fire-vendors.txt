# SinkSeal live-fire vendor table (read by sink-inventory-drift.sh)
#
# [Why this table exists]
# no-live-fire-check.sh only asks "does an un-allowlisted file touch a *known* sink
# pattern?" So if a project adds a new live-fire vendor and forgets to add a matching
# pattern to sinks-default.txt / .forge/sinks.txt, that sink stays invisible to the
# scan and silently shows "pass." The ledger rots quietly. This table exists to let a
# machine notice that rot.
#
# [Verdict]
#   presence (vendor appears in a dependency manifest)  AND
#   no coverage (no line in the sink pattern tables matches the coverage regex)
#   -> violation: "a live-fire vendor is present but no sink pattern catches it."
#
# [Format]  vendor;;presence;;coverage;;category
#   presence : regex matched case-insensitively against dependency manifests
#              (package.json, requirements.txt, etc.)
#   coverage : regex matched case-insensitively against each line of the sink pattern
#              tables. Any single match counts as covered.
#
# Add project-specific vendors in .forge/vendors.txt using the same format.
# Vendors judged not to be live-fire in a given project go in .forge/vendors-allow.txt
# (with a reason comment — these are audited periodically).
